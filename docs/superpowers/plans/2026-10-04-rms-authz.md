# RMS authentication and authorization repair

Scope: APP-BT-001 through APP-BT-006, APP-BT-016, and directly coupled identity/role paths. Do not change the source audit workbooks.

1. Add failing API tests against the authorized test database for anonymous access and forged identity/role headers. Preserve a legitimate login/own-data control.
2. Add a versioned, reversible `AuthSessions` migration with only additive DDL, verify the pre-change backup, and validate the existing row counts and foreign keys before and after applying it. Never run schema DDL at API startup.
3. Replace the Base64 token with a cryptographically random bearer token. Persist only its digest, issue it after credential verification, enforce expiry and revocation, resolve the current employee from the database on every request, and expose `me` and `logout`.
4. Require authentication on all non-login controllers. Derive actor ID and role only from the validated principal. Apply route-level authorization and owner/team/HR/Board scoping, including direct ID reads and filters. Block cross-team manager decisions.
5. Update the frontend to send only the bearer credential, discard untrusted role headers, refresh profile from `me`, and use a limited substitute directory for ordinary employees.
6. Verify negative authorization paths, legitimate paths, frontend build/lint, DB invariant queries, and preserve regression evidence in the progress/report files.

Stop condition for this phase: all covered routes reject anonymous/forged identity, legitimate role paths work, no known security bypass in these paths, and evidence is recorded. Remaining report findings stay open until separately tested and repaired.
